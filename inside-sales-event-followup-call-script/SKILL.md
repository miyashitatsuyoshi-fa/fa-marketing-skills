# イベント後フォローアップ架電スクリプト設計スキル

ファーストアカウンティング（FA）のインサイドセールス／営業担当が、イベント・セミナー参加者へ「お礼＋次アクション獲得」のフォローアップ架電を行うためのトークスクリプトと戦略を、CRM情報から設計する。単なる定型文ではなく、**その相手の温度感・過去経緯・課題に最適化された**スクリプトを作ることがこのスキルの価値である。

架電の目的は多くの場合「売り込み」ではなく「次の商談機会（アポ・ヒアリング）の獲得」である。相手に話してもらい、課題と検討状況を引き出すことを最優先に設計する。

## 入力

SalesforceのコンタクトCRM情報（JSON等）。主に以下を参照する：

- **contact**: 氏名 / title（役職）/ department / position_class / approach_status（アプローチ状況）/ apoflag / opportunity_flag / ng_list / last_activity_date / owner / account（会社名）
- **opportunity**: name / stage（商談ステージ）/ amount / close_date / solution_type / lead_channel / owner / created_date
- **activity_history**: 各接触の subject / date / type / approach_status（不在・通話済等）/ description_summary

情報が一部欠けている場合は、欠けている前提を明示したうえでプレースホルダ（例: 【イベント名】）を使って作成し、架電前に埋めるべき項目として指摘する。

## 出力フォーマット（必ずこの4部構成）

### ① 状況整理
架電前に押さえるべきポイントを**表形式**で整理する。最低限、次の観点を含める：

- **相手の属性**: 役職・部門から、実務課題の当事者か／意思決定者か／推進担当かを読む。経費精算・経理・財務系の役職なら、請求書・領収書処理が本丸の課題領域。
- **温度感**: 過去にイベント参加・発言があるか。自らビジョンや課題を語った履歴（例: Peppol・DX・電子化への期待）があれば「語りたい人」＝共感から入ると強い。
- **過去商談（最重要）**: `stage` を必ず確認する。`Closed Lost`（失注）の場合、**失注理由の把握を今回の主目的に据える**。失注を無視して売り込むと「分かっていない営業」と映り逆効果。`Closed Won` や進行中なら別アプローチ（アップセル・進捗確認）。
- **直近接触とブランク**: `last_activity_date` と `approach_status`（不在が続いていないか）を確認。長期ブランクなら、まず「ご無沙汰」の再接続が必要。
- **データの整合性**: `approach_status` が「未アプローチ」でも活動履歴があることがある。履歴を踏まえた「再アプローチ」として臨む。架電後は必ずCRMの活動履歴・ステータスを更新する。
- **キーマン**: 過去メールのCC等に他の関係者がいれば、単独決裁でない可能性。共同検討者を確認対象にする。

### ② 架電スクリプト
次の流れで、実際に読み上げられる話し言葉で作成する。各ステップで「相手に話してもらう」合いの手を入れる：

1. **オープニング**（名乗り・本人確認・イベント参加のお礼・所要時間の許可取り「2〜3分よろしいでしょうか」）
2. **関係想起・アイスブレイク**（過去の接点や相手が語った関心事に触れ、口を開いてもらう。ここで一度止めて相手に語らせる）
3. **ヒアリング（本題・最重要）**: 過去失注があれば率直に理由を尋ねる。聴くべき3点を必ず押さえる —
   (a) 過去失注/見送りの真因（予算／機能／社内合意／タイミングのどれか）
   (b) 現在の最重要課題（工数削減か、内部統制・不正/二重支払い防止か）
   (c) 意思決定の座組みと時期（誰が・いつ判断するか）
4. **価値提示**（相手の課題に合わせてソリューションを**1つだけ**提示。製品の対応は下記「FAソリューション対応表」を参照）
5. **クロージング**（オンライン15〜20分等のハードルの低い打診を、**二者択一の日程提示**で確定。難しければ「資料送付＋次回連絡日の合意」を最低ラインにする）

### ③ 注意点
その案件固有の留意点を箇条書きで。汎用的には以下を常に検討する：
- 失注案件を「なかったこと」にしない。
- 売り込みすぎない（聴く7：話す3）。相手が語りたいタイプなら特に。
- 直近が「不在」続きなら、架電の時間帯を変える／固定電話→留守電・メール予告→携帯の順を検討（いきなり携帯は警戒されやすい）。
- 役職とスコープのズレ（現場実務の当事者か、全体DXの企画側か）を見極める。
- 社内の他キーマン・共同検討者を必ず確認する。
- 制度の追い風（電子帳簿保存法・インボイス制度・Peppol対応等）を再接続の自然な口実に使う。
- 架電後にCRMの活動履歴・ステータスを更新し、商談オーナーと情報連携する。

### ④ 想定オブジェクションハンドリング
**表形式**で「よくある断り文句 → 切り返し」を用意する。最低限、次のパターンを相手の状況に合わせて具体化する：
- 「前に検討したけど見送った」→ お礼＋当時の懸念の今の解消状況へ誘導し、真因を聴き出す
- 「今は困っていない／落ち着いている」→ 否定せず、制度変化を口実に「現状で問題ないかの確認」＋最新事例の資料送付提案
- 「忙しい／時間がない」→ 2分で要点1つ→後日15分の二者択一打診
- 「担当が変わった／管轄外」→ お礼＋現担当者の紹介依頼（名前を借りる許可取り）
- 「他社ツールを入れた／検討中」→ 選定の重視点を聴く＋FAの強み（読取精度・照合/不正検知の自動化）で差別化、比較材料提案
- 「価格が高い」→ 規模別プラン・スモールスタートの提示＋工数削減とリスク低減まで含めた費用対効果・試算の提案
- 「資料だけ送って」→ 送付を承諾しつつ、送付内容を最適化する名目で課題を1問ヒアリングし次回接点の布石にする

## FAソリューション対応表（価値提示で使い分ける）

相手の課題に応じて提示するソリューションを**1つに絞る**：

- **入力・確認の工数がネック** → 請求書・領収書のAI自動読取（Robota / Remota）。入力・目視確認の工数を削減。
- **内部統制・監査・不正対策がネック** → Digital Audit Service（AI＋RPAで照合・不正検知・二重支払い防止を自動化）。
- **現場からの起票・申請のばらつきがネック** → 現場起票のDX（請求書の現場起票フローの標準化・自動化）。

迷ったらヒアリングで課題を特定してから出す。製品名・サービス名は最新の社内呼称に合わせて適宜確認する。

## 作成時の心構え

- スクリプトは「読み原稿」であると同時に「分岐の地図」。相手の反応で枝分かれすることを前提に、合いの手と次の一手を用意する。
- 1回の架電で全部を売らない。目的（アポ獲得／失注理由把握／キーマン特定）を1〜2個に絞る。
- 相手を一人の人間として扱う。過去に語った言葉を覚えていることが、最大の信頼構築になる。
- 個人情報（電話番号・メール）は架電準備以外の目的に使わない。
